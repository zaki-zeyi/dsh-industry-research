# 飞书连接与恢复（当前实现）

以当前 release 基线为准：应用登记与个人文档授权分两步，个人授权由用户手动确认。旧版本的自动完成、Bearer切换、union_id切换状态机和原流程重试保存已不作为当前连接契约。

1. 点击「绑定飞书」「更换应用」或「重新绑定」，扫码登录并选择/创建应用。
2. 应用登记成功且本机凭据保存成功后，生成该应用的个人授权二维码。
3. 使用本次登记账号扫码授权，点击「我已授权」，服务端验证应用ID、账号及必需权限。
4. 验证通过后点击「完成」返回工作台。个人授权账号与应用登记账号不一致时拒绝绑定；更换账号需重新登记对应账号的应用。

扫码等待期间不自动交换device code。手动确认期间重复发起新流程返回409，保留正在确认的流程。重新获取二维码后旧二维码失效，取消、过期和关闭后的迟到结果不能提交绑定。

重复App ID复用对应profile并更新新凭据，不更改CLI默认选择，不新建重复配置。App Secret仅通过stdin传入CLI，不返回前端或写入业务设置。

凭据保存失败显示失败并保留原应用设置。用户修复本地CLI/权限后点击「重新获取应用绑定二维码」重新登记；保存结果不确定时不误报成功。机器人权限修复固定当前应用，不切换个人账号。

目录读取权限用于首次发现/导入，为可选能力；缺失时不阻断已有绑定和调研。机器人健康检查独立呈现。新建目录前仍需查询确认唯一性，详情见目录管理说明。

## 日志与异常

通过平台日志的飞书连接监测检查 app_registration、qr_generation、credential_storage、authorization_confirm、identity_check、binding_validation 等阶段。同一操作可按traceId关联。

- 密钥故障只依据实际dpopKeyStatus与明确错误信息判断；字段名出现DPoP不代表故障。
- 二维码生成失败记录LARK_QRCODE_GENERATION_FAILED，保留原绑定。
- 临时轮询错误在下一次成功响应后清除，不遮挡恢复后的二维码。
- CLI未安装、不可运行、网络和账号不匹配分别提示；不自动注销、不切换登录机制。

真实飞书扫码及企业授权需用户本人确认。自动测试使用隔离SDK/CLI夹具，不等同于生产账号授权验收。
