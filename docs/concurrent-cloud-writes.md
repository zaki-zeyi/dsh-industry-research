# 飞书文档保存队列

同一个工作台实例允许同一用户的多个调研会话并行。Agent 把事实增量和报告通过 stdin 提交。平台先将正文存入用户飞书云空间的保存草稿，读回验证后，把草稿链接、任务和保存项目一起提交到 SQLite。收到入队确认后 Agent 即可结束。调研时限在入队时停止计时。

- 公司和专题正文按实际飞书文档排队。首次创建唯一文档时按父目录和业务标识查找并复用。目录创建只协调同一父目录下的同名子目录。
- 日报、周报和其他独立报告并行创建。专题本期日报和专题总报使用不同的保存项目。
- 本任务的报告、公司正文和其他交付文档全部写入并核对后，才处理索引。公司索引独立读取并合并最新条目。等待索引期间其他任务仍可以更新正文。
- 平台读取最新文档版本，按事实键、日期及读回内容去重，局部更新正文。模型负责提交事实与冲突信息，后台保存只执行确定性的合并规则。
- 网络失败后平台按退避时间复核。重启后重新读取未完成的保存项目和草稿，已经核对的文档无需重新调研。创建响应不确定时先找回文档，保留已经确认的链接。授权或文档冲突需要修复时，工作台重试复用原提交。

SQLite 保存队列和核对所需的元信息，正文留在飞书草稿及交付文档。该队列协调一个运行实例内的写入。飞书版本号用于发现写入期间的外部编辑。

`tests/queued-saves.test.mjs` 验证真实 HTTP 提交入口、同公司重复事实、跨公司并行、独立报告并行、索引单独合并和重启续跑。原生宿主验收使用 `scripts/native-host-acceptance.mjs` 和隔离的模型与飞书夹具。
