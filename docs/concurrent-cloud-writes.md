# 飞书保存并发控制

Agent 负责检索、语义合并和飞书正文写入；平台负责保存准入和轮次隔离。检索阶段不占保存锁。共享公司索引目前仍被多个业务修改，因此同一应用、根目录的信息库继续串行保存；不同信息库互不影响。

## 保存流程

1. Agent 完成检索后调用本轮独立的 `cloud-write-config-<binding>.json` 申请保存锁。
2. 平台解析唯一目录并返回最新链接和索引；Agent 重新读取远端内容再合并。
3. 平台生成的 Lark CLI 入口在每次写命令启动前检查任务、绑定、requestId 和锁归属，并持久化在途操作。只读命令无需持锁；未知命令按写操作处理。
4. CLI 退出后确认本次操作结束；回传交付结果后释放保存锁。

每个绑定使用独立的 CLI 配置目录，避免重试覆盖旧配置。失败或取消的旧轮次不能启动新写命令；已启动的命令结束前不得把锁交给下一任务。在途记录跨插件服务重启保留。准入操作 ID 由客户端生成，避免准入响应丢失后无法确认结束。

宿主确认同一串行会话的新 turn 启动时，旧绑定可标记为已结束；未结束的在途命令仍然阻止交接。原生 Retry 只有在失败执行之后的新 turn 才能重新申请锁，已取消任务不能据此恢复。旧轮次回执不能完成新绑定。

## 边界

- 当前控制覆盖平台生成的 CLI 入口，不能阻止 Agent 绕过它直接调用原始 CLI 或其他写入工具；完整隔离需要宿主侧的工具执行权限控制。
- CLI 返回或退出不能提供跨多个飞书文档的事务。部分写入后失败，重试仍需先读回核对并复用已有文档，不能盲目重复创建。
- 已发出的远端请求无法通过撤销本地权限撤回。进程崩溃、结束确认丢失等不确定情况保留在途记录并拒绝抢锁，需要核对实际保存结果；不使用超时强制解锁掩盖不确定状态。
- 本次没有把事实正文迁入本地数据库，也没有引入额外插件依赖。

## 验证

`tests/cloud-write-admission.test.mjs` 覆盖无锁拒绝、轮次失效、在途交接、重启保护、只读分类、原生 Retry 以及真实 CLI 子进程的 stdin 和配置隔离。`tests/parallel-research.test.mjs` 覆盖并行检索、串行保存、取消等待者和丢失结束事件后的恢复。隔离宿主验收通过 `scripts/native-host-acceptance.mjs` 执行，使用真实 DSH、模拟模型与飞书 CLI，不写线上文档。
