# 0.8.12：已有目录复用及历史重复目录兼容

基于 merge-dev 的 20226ee，在 codex/fix-feishu-folder-reuse 分支修复。

截图中的提示来自 cloud-publications 的历史刷新：只要根目录下有多个同名目录就抛错，即使写入侧已经记住了目录 ID，刷新仍会失败。该提示本身不能证明本次任务刚刚创建了重复目录。

写入侧在没有本机缓存时也会拒绝已有重复目录；日报回执还会覆盖并丢失 rootFolderToken，削弱后续升级时缓存归属判断。原生会话 CLI 入口此前只转发命令，没有拦截自行创建目录的请求。

## 新行为

- 目录名称进行 NFC 和首尾空白规范化；重复分页及快捷方式按真实 token 去重。
- 新写入优先复用已确认目录。没有确认记录时复用创建时间最早的已有目录；缺少时间或并列时按 token 排序，固定选择并持久化，不依赖 API 列表顺序。只有完整读取后没有匹配目录才允许新建。
- 日报、周报及内部资料历史刷新读取所有同名目录中的报告，按链接去重；不删除旧目录，不移动或覆盖旧报告。任一读取失败时保留原缓存。
- 日报/周报交付保留根目录归属字段。
- 云端任务的原生 CLI 入口拒绝 drive +create-folder 和 drive files create_folder，要求使用保存锁返回的目录；服务端继续在保存锁内解析和创建。旧手动上传流程保持兼容。

目录读取与创建使用同一套飞书 CLI。读取失败、分页不完整及创建结果不确定时继续禁止盲目重建。不同机器同时首次初始化时，飞书 API 并不提供按名称原子创建保证，不能声称全局分布式唯一。原生模型若绕过插件入口另行调用其他工具，也不属于此入口可强制控制的范围。

公司索引本身存在多个同名文档时仍需人工核对，不能自动猜测如何合并内容。本次不会删除用户的云端数据。

新增回归覆盖重复目录的历史读取、读取失败保留缓存、写入选择稳定性及会话创建拦截。飞书返回使用夹具；真实账户目录没有执行删除、迁移或创建。
