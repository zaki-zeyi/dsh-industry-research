# 用例、埋点及 CI 日志整改（2026-11-10）

本轮先处理诊断与用例准确性，不把账号切换/自动恢复等未完成实现改成通过。

## 修改

- 身份检查根据 dpopKeyStatus 的实际值和明确错误消息分类，不再将成功响应的整个JSON交给DPoP关键词正则。有效密钥、Bearer未返回密钥字段均不误报；missing/unavailable/invalid/error及明确DPoP错误仍报警。
- 二维码生成失败返回稳定的 LARK_QRCODE_GENERATION_FAILED，并记录 qr_generation 阶段失败事件。测试夹具新增故障开关，真正执行失败分支。
- 对齐可选目录读取权限和独立机器人健康检查的测试；保留缺少目录权限仍可绑定的业务断言。
- 重复App ID用例验证冲突后更新同一profile、配置不重复、默认选择不变；错误App ID仍必须拒绝绑定和调研。
- 应用登记与个人授权分阶段测试按现行release基线验证，未确认个人授权仍不能使用新应用；有效旧绑定不因未使用的登记二维码被阻断。
- 初次绑定浏览器用例移除无效的旧切换账号字段；账号重新绑定的差异断言仍保留失败。
- 配置生成测试注入平台/命令，避免依赖CI机器实际安装DSH；真实CLI安装仍由独立集成验收负责。
- CI拆分构建、单测与浏览器测试。构建成功后，即使单测失败也运行浏览器；打包发布仍要求前序全部成功，不使用continue-on-error。
- CI收集每阶段输出、Playwright报告/截图/trace和Store白名单运行埋点。临时夹具删除前导出运行日志，不复制业务表、密钥或原始CLI输出。

## CI runner 修复

实际读取 macOS check annotation，取消原因是 `macos-14-arm64-us-default is not supported`。GitHub 官方公告确认 macOS 14 于2026-11-02退役；两个工作流均改用 macos-15。来源：https://github.blog/changelog/2026-10-01-github-actions-macos-14-runner-image-retirement/ 。

macOS 15 首轮CI已实际运行，暴露2项额外旧断言：临时目录 `/var/...` 与子进程返回的 `/private/var/...` 是同一目录的别名。cwd测试改用 realpathSync 比较真实目录，仍严格验证输入和退出码，不修改CLI实现。首轮附件已下载核验，包含62份runtime日志、7份失败trace及截图。

Windows首轮附件另发现preparePty并发初始化竞争：多个单测worker同时复制同一conpty.dll，触发EBUSY，导致analysis.test.mjs整文件未加载。CI封装在并发单测前串行执行原有prepare-pty脚本；生产多实例初始化的同类竞争保留为待评估实现问题，不通过忽略复制异常掩盖。
