# 当前飞书连接契约及验收

2026-11-10，按用户明确要求“飞书连接以当前实现为主”，当前分阶段、手动确认的连接方式作为验收依据。

- 应用扫码登记后生成个人授权二维码，用户点击「我已授权」触发令牌交换与验证。
- 更换应用/重新绑定均重新进入应用登记，生成不同流程；个人授权须与本次登记账号一致。换账号先登记对应应用，不根据旧union_id状态机强制切换/回滚。
- 个人授权换成不同于当前登记账号时必须失败，不能直接覆盖ownerOpenId。重新登记新账号后可成功绑定。
- 失败后由用户重新获取二维码重试；保存超时不误报成功，再次登记复用已落盘profile。
- 操作中拒绝冲突请求，保留当前流程；取消、过期、迟到回调不得提交配置。
- 不自动更改DPoP登录机制，不依赖旧版autoComplete、retrySave或pendingApplicationOperation内部方法。

本轮将原有19项旧契约单测与7项旧页面断言替换为上述外部可观察行为的正反例，没有使用skip或todo绕过。实际UI缺陷（轮询成功后旧错误不清除）已修复，并由原有用例验证。

本地完整测试334/334通过，Chrome浏览器40/40通过，生产构建通过。真实DSH隔离宿主加载官方Schedule后，原生调研、日报回执、通知夹具、Schedule创建/停用及三会话并行保存验证通过。真实模型和飞书写入仍使用本机夹具，不冒充真实账号生产验收。

原生宿主浏览器验收兼容中文「继续」和英文Continue预览提示。最终发布以前还需核对CI与实际打包安装结果，相关记录在PR #1。
