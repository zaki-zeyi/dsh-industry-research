# 0.6.13 历史任务重试通知发送给当前用户

用户点击日报、周报或内部资料的“重试通知”时，使用当前绑定应用，通过 `auth status --json --verify` 获取该应用下当前用户的 openId。个人身份未验证、应用返回不匹配、当前绑定账号不匹配或机器人身份不可用时，拒绝发送并保留错误，不显示成功提醒。

不再要求手动重试先恢复历史任务的原应用。不会把旧应用的 openId 或 profile 用到新应用；默认配置也不会继承历史任务的 profile。服务自动发送和恢复调度的默认路径仍使用任务的原接收目标，此次改变限定于明确的手动重试操作。

飞书返回成功后更新最新通知目标，但保留研究任务 `feishuApp` 和报告文档归属。目标发生变化时，卡片显示：

> 当前绑定的飞书账号或应用已发生变化，已通过当前应用向当前用户发送通知。

此提示只在成功后显示，失败不会冒充“已发送”。通知日志记录原/当前应用 ID，不记录个人 openId 或消息正文。界面不再重复展示同一条服务端失败文案。

原目标保持原幂等键；更换应用或账号后使用按任务、应用及接收人派生的稳定 UUID 幂等键。同一新目标失败重试保持同一个键，避免重复通知；已经成功的任务不会因再次点击或重复 API 调用而重发。

0.6.12 文档中的“先恢复原绑定再重试”限制已由本版本的手动重试策略替代。此次仅修改通知目标，不迁移飞书文档，也不自动变更文档权限。

验证使用模拟 CLI 与浏览器接口；没有在用户真实环境发送测试消息或更新真实任务数据。
