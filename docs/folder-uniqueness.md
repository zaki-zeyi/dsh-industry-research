# 0.8.9：合并开发分支与飞书目录唯一性

合并来源：`feature/merge02-04-dev`，提交 `d3d3610`。保留 `merge-dev` 的任务阻塞定位、完成/停止提示和原生会话入口，合入条目级合并规则及公司索引被删除后的目录重新发现。

## 原因

旧提示词在本机缓存没有子目录 token 时要求“首次创建一次”。本机缓存按应用、账号或配置隔离，不能证明共享飞书目录中不存在同名文件夹，因此换应用、换账号或另一台机器首次运行会重复创建。重试和扩大超时不能消除这个逻辑错误。

友商分析刷新另有 Windows 启动问题：直接执行无扩展名的 CLI 路径，没有经过已有的 `larkLaunch`，可能在 CLI 已安装时仍返回“未找到 Lark CLI”。现已统一使用启动器，保留选定 profile，不回退默认应用。

## 行为

- 原生任务在保存锁内由服务端解析目录；Agent 只使用锁返回的真实 token，不能自行创建文件夹。返回快照同时包含 `analysisIndex`。
- 根目录没有 token 时查用户云盘根目录；业务目录在实际选定父目录下查找。完整查询后只有一个同名文件夹就复用，没有才创建。同名普通文档不算文件夹。
- 覆盖全量信息库、日报、周报、友商分析、内部资料及其原始资料/逐字稿/会议纪要子目录。已有公司索引和分析报告索引优先复用。
- 已确认目录的缓存以实际父目录 token 和名称为键，不因换应用或账号而重复创建同一共享子目录。根目录切换不会使用旧父目录下的业务目录。
- 分页未完成、读取失败、响应格式异常或多个同名目录时停止，不把这些情况当成“不存在”。首次发现未知目录需要目录读取权限，已确认的 token 复用不必重复列目录。
- 创建前持久化待确认记录。网络超时或进程异常后，下一次先查询：找到结果则恢复；仍未确认则不重复创建。CLI 未启动或飞书明确拒绝请求可修复后重试。
- 当前服务内的目录解析按队列串行，防止本机跨任务、跨 profile 竞争。飞书没有按名称原子 get-or-create 的保证；不同机器同时首次创建同一目录仍应避免并发初始化。建议团队预先设置共享根目录并完成目录初始化。
- 平台日志记录目录解析开始、成功、失败、任务编号、分类错误码和耗时，不记录密钥、令牌或正文。

## 已存在的重复目录

升级不会删除、合并或迁移云端文件夹。没有已确认目标时检测到多个同名目录会报冲突，请先在飞书核对内容和共享权限，整理为一个目标目录后重试。不能仅按所有者或列表顺序自动选一个，避免写到错误目录。

## 验证范围

`tests/folder-uniqueness.test.mjs` 覆盖无缓存复用、默认根目录、并发保存、另一机器缓存为空、分页、已有重复目录、权限与网络故障、创建结果不确定、切换根目录、多层内部目录、取消、保存锁返回值、索引冲突、真实 Node 子进程 CLI 启动，以及通过 HTTP 保存锁的原生任务交付。

飞书服务与宿主会话使用测试夹具；没有对真实云端目录进行创建、删除或迁移。实际账号的目录权限和安装后的真实写入需在用户环境验收。
