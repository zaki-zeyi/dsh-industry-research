# 0.8.14：页签切换的缓存复用与请求去重

0.8.13 安装包中，日报/周报/内部资料页签进入时先发 `refresh=true`，等飞书目录扫描完成后才渲染；日报与周报共用同一个 `Briefings` 实例，切换 `kind` 时没有隔离 `items`，扫描期间仍显示上一页卡片。根组件另外每 4 秒重读配置、公司库、分析报告和任务列表，友商分析切换还会再调一次 `load()`。

本版按「先修正确性，再改刷新策略」处理。

## 新行为

- 日报、周报、内部资料按「当前应用 + 账号 + 根目录 + 页签」分别保存 `items`、`syncedAt`、错误和加载状态。切换页签立即显示目标页签自己的缓存；没有缓存只显示该页签的加载占位，不再沿用上一页卡片。
- 卡片渲染再按 `briefing.kind` 过滤一次：明确标为另一类报告的卡片不会出现在当前页签；没有类型字段的历史记录仍按服务端结果展示。
- 进入页签先读本地缓存（不访问飞书），再在后台同步。远程刷新不阻塞首屏，缓存命中时切换页签不等待网络。
- 缓存有效期 60 秒：有效期内重复进入同一页签复用结果；手动「刷新」使用 `force=true` 强制同步。
- 同一范围的远端刷新合并为一次：客户端同一 scope 只保留一个同步 Promise，服务端按缓存键共享进行中的读取，连续点击或开多个窗口都不会重复启动 CLI。
- 每个 scope 带请求序号：较早发出的读取或同步结果如果已被更新的请求取代，不再写回界面。
- 后台同步失败时保留当前页签缓存，展示错误原因、上次同步时间和「重试同步」入口；失败不推进 `syncedAt`，下一次仍会真正读取。
- 仅当当前页签存在 `running`/`queued` 任务时才 4 秒轮询，其余情况 30 秒；页面隐藏时所有轮询暂停，回到前台立即补读。配置、公司库、分析报告不再每 4 秒重读，仅在进入页签（60 秒 TTL）、手动刷新或页面加载时读取。

## 服务端接口

- `GET /api/briefings?kind=daily` 与 `GET /api/internal-materials` 为纯缓存读取，返回新增的 `syncedAt`。
- `refresh=true` 在 60 秒内复用上次成功同步结果；`refresh=true&force=true` 绕过有效期。同步失败仍返回 200、保留缓存卡片并带 `syncError`。
- `/api/industry/library`、`/api/analysis/reports` 的 `refresh=true` 只做进行中请求合并，不改变原有语义。

## 边界

4 秒轮询大多读本地缓存，真正耗时的是进入页签时的远端刷新：日报/周报至少两层目录读取，内部资料至少三层，每层都可能包含 CLI 启动、网络和分页。本版消除的是「每次进入都等远端」和「不必要地重复读取」，不改变飞书目录本身的读取成本，也不缓存失败结果。

## 验证

- `tests/tab-store.test.mjs`：缓存优先、页签隔离、迟到响应不覆盖、同范围只同步一次、60 秒有效期、失败保留缓存与退避重试。
- `tests/performance-tabs.test.mjs`：并发刷新只读一次飞书、60 秒复用、`force` 生效、失败保留缓存、内部资料缓存不重复扫描三层目录。
- `tests/e2e/performance-tabs.spec.mjs`：慢响应/快速往返不串页、有缓存先显示、同范围 60 秒只同步一次、失败保留卡片并重试、内部资料先缓存后同步。
- 原有 334 项单测与 40 项浏览器用例保持通过。
