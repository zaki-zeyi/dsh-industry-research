# 官方 Git 更新真机验收

验收日期：2026-11-26。环境为用户实际使用的 Windows 桌面 DSH，宿主插件管理器版本 0.2.2-rc.3。

## 已实现的入口

DSH 官方插件详情页的 actions、badge 和 section 扩展位显示检查更新、可更新标记、目标版本按钮及更新结果。按钮由行研工作台提供，连接本插件更新服务，实际替换调用官方 `pluginManager.updateBundle()`，来源固定到本仓库的预构建 Git 提交，无需发布 npm 包。

GitHub 不可变 Release 发布后，CI 自动更新 `dsh-plugin-index.json`。本次发布的版本为 0.13.21，安装提交为 `940bd5fd450f3fb7b9e240c262e0a932297419d6`。

## 两轮桌面验收

通过 Playwright CDP 连接用户的实际 `dsh-app://app/` 窗口，在官方详情页点击“更新到 0.13.21”。安装通过页面按钮触发，结果再由宿主安装记录、工作台健康接口和进程身份交叉核对。

| 起始版本 | 目标版本 | 页面最终结果 | 安装与运行版本 | DSH / Host 重启 | 公司索引 |
| --- | --- | --- | --- | --- | --- |
| 0.13.20 | 0.13.21 | 更新完成 | 均为 0.13.21 | 均未重启 | 9 家，内容摘要一致 |
| 0.13.19 | 0.13.21 | 更新完成 | 均为 0.13.21 | 均未重启 | 9 家，内容摘要一致 |

第一轮验证持久化更新协调；第二轮通过 DSH 原生安装入口准备较旧版本，再验证旧更新器的兼容升级。首次从本地安装迁移到固定 Git 来源时进行过宿主重启，表中的两轮按钮升级和第二轮基线准备均使用同一组 DSH / Host 进程。完成后已恢复用户原先开启的空闲自动更新配置。

本地证据位于 `artifacts/official-git-update/0.13.21/from-0.13.20/` 和 `from-0.13.19/`，包括升级前截图、完成截图、版本与进程核对以及公司索引摘要。第二轮观察曾因验收脚本读取到上一轮同目标版本的结果而提前结束；修正为按提交的操作 ID 区分后继续观察同一次真实安装，完成全部最终断言。

## 实测修复与检查

实际宿主可能先返回安装已应用，工作台稍后才完成健康检查与启动。更新器现在等待与操作 ID、目标版本和宿主进程匹配的健康回执，再报告完成。旧更新器的早期确认错误，仅在新版确已健康启动且版本来源匹配时校正；其他失败保留原结果。持久化租约使完整 Git 更新与本地槽位安装互斥。

40 项更新专项回归通过，涵盖延迟健康确认、独立模块实例、进程退出后租约恢复、离线安装、重复请求、错误来源、失败恢复及版本不符。最终版本的 Windows/macOS 构建、完整测试、浏览器、打包与安装验证，以及 Windows 真实宿主更新检查均通过：[发布工作流](https://github.com/zaki-zeyi/dsh-industry-research/actions/runs/45777943633)。

## 保留自有机制的结论

保留完整包下载缓存、空闲时业务更新和本地恢复；基础包、启动层与客户端扩展的完整更新由官方 Git 路径负责。官方 Git 检查及安装需要联网；自有业务槽位在完整包下载并校验后，可以离线切换和恢复。两条路径的范围见[机制说明](official-git-update.md)。
