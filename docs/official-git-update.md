# DSH 官方 Git 更新接入

## 两条入口

DSH「插件 → 行研工作台」详情页使用官方 `plugins.detail.actions`、`plugins.detail.badge` 和 `plugins.detail.section` 扩展位。按钮和更新提示由本插件提供，调用同宿主的 `/industry-research/official-update` 更新服务，最终由官方 `pluginManager.updateBundle()` 完成完整插件的替换。没有 npm 发布或第三方插件依赖。

工作台「设置 → 版本与更新」保留完整包下载和本地槽位切换。官方详情页的「本地安装包更新」也连接同一服务。保留这条路径，是为了支持包已下载后的离线安装、自动等待任务空闲以及健康失败时从本地旧槽位恢复。更新业务槽位不会更新 DSH 管理的基础包或浏览器扩展代码；完整插件更新使用官方 Git 入口。

## 发布与来源

两个入口共用不可变 GitHub Release 的 `update-manifest.json`，核验清单摘要、源码提交、安装提交和归档信息。官方更新固定到 `installCommit` 对应的预构建安装提交，不能使用源代码提交或浮动 `#release` 分支。目标仓库固定为 `zaki-zeyi/dsh-industry-research`，不读取 npm 同名包。

DSH 官方管理器要求当前安装来源也为同仓库的完整 40 位 Git 提交。从本地目录、ZIP/TGZ 或浮动分支安装的用户，先通过 DSH 原生添加插件入口安装一次固定提交版本。数据目录保持原路径。已有的 `dsh-plugin-index.json` 提供官方「发现」页安装和更新所需的固定提交。

## 在线与离线

官方 Git 路径在检查版本和安装阶段需要网络；包管理器是否命中缓存不作为离线安装承诺。DSH 负责报告安装结果，支持 HMR 时热加载，不支持时明确提示需要重启。官方失败恢复也按宿主的原来源重新安装。

本地路径检查和初次下载需要网络。完整归档校验并缓存后，本地切换和旧槽位恢复不需要网络。断网时无需重新检查版本，可直接安装已校验的缓存版本。

## 并发、结果和日志

两个入口共用按数据目录区分的持久化更新租约。官方更新暂停任务接收前检查正在执行的 Agent、队列、保存和请求。租约独立于 DSH 热加载的模块实例，并记录所属进程；所属进程退出后可重新获取。不在卸载回调中等待自身更新完成。

官方操作状态独立原子写入数据目录的 `updates/official-update.json`。新版启动后先验证健康并启用服务，再写入与操作 ID、版本和当前宿主进程对应的健康回执。旧实例在官方安装流程返回后等待该回执，同时核对 DSH 安装版本和固定来源，才显示更新完成。宿主重启要求、失败、恢复及未完成操作分别报告，记录导入平台更新日志。进程退出留下的未完成操作显示中断，重新检查后可重试，不猜测成功。

## 验证

`tests/official-update.test.mjs` 覆盖固定来源、错误仓库和同名 npm 包拒绝、运行中任务保护、两入口互斥、重复点击、卸载后结果读取、失败恢复、版本不符、健康未确认、离线检查和中断状态。已从用户实际桌面的官方详情页完成两轮按钮升级，核对真实安装源、运行版本、公司索引及宿主进程身份，详见[真机验收记录](official-git-update-acceptance.md)。
