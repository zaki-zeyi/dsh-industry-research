# 0.8.10：全局飞书 CLI 环境

## 原因与范围

0.8.9 只补齐了友商分析刷新中的启动器调用。全量信息库、日报、周报和内部资料虽然已间接经过启动器，仍有各自的执行封装；原生会话里的提示词则直接要求执行 `lark-cli`。桌面后台与会话终端的 PATH 不一致时，可能出现后台正常、会话找不到命令的情况。

现在认证、索引读取、目录枚举/创建、公司库和友商刷新共用 `server/lark-cli.mjs`；日报、周报及内部资料历史同步通过同一入口读取目录。Windows 优先原生 EXE，处理 `.local/bin`、PATH、npm 安装路径和显式 shim，避免 PowerShell `.ps1` 执行策略拦截。显式路径失效不回退另一个 CLI。macOS/Linux 也会查用户安装目录和 PATH。

## 原生会话与上传

创建原生会话或准备上传时，在任务目录生成 CLI 启动脚本与仅含命令路径/前置参数的配置，提前保存平台解析出的可执行文件路径。各类任务的提示词固定使用此入口和任务所选 profile；不依赖会话恰好继承后台 PATH。保留 stdin、调用时 cwd、stdout/stderr 和退出码（包括高风险确认退出码 10）。二维码和附件的相对路径语义保持不变。脚本和配置不包含 App Secret、用户 Token 或设备码。

已有会话不会自动重新提交；重试任务或准备旧报告上传时更新启动入口。授权与业务错误不被当作 CLI 未安装，账号和机器人权限仍分别验证。

## 未安装或不可运行

- `GET /api/feishu-cli` 只执行 `--version`，区分未找到、无法运行、版本响应异常和可用。探测不会发起登录、修改应用、安装软件或发送消息。
- 「平台日志 → 飞书连接监测」提供环境检查；绑定失败及页面报错也能进入相同指引。未安装时显示官方安装说明、Node.js 下载入口、可复制命令和重新检测按钮。
- Windows 指引命令为 `npx.cmd --yes @larksuite/cli@latest install`，使用 `.cmd` 避免 npx 的 PowerShell 脚本策略问题；macOS/Linux 使用 `npx --yes @larksuite/cli@latest install`。来源：[Lark CLI 官方安装说明](https://github.com/larksuite/cli#installation--quick-start)。
- 桌面版在运行 DSH 的电脑安装，网页版在插件服务所在机器安装。安装后重新检测；已配置的显式路径失效时需修正 `LARK_CLI_COMMAND`。插件不修改系统 PATH、不清理凭据、不切换账号，也不静默执行安装命令。
- 真实环境发起应用登记前先检查 CLI 可运行性，缺失时停止二维码登记并显示安装帮助；异步检查结束后再次验证任务空闲保护。

## 验证

`tests/lark-global.test.mjs` 使用真实 Node 子进程验证全量库、友商分析、日报、周报、内部资料、目录解析和认证；覆盖 PATH 缺失、Windows 中文/空格/单引号路径、stdin/cwd/退出码、原生会话启动文件、旧上传、环境错误分类与只读检测接口。飞书业务响应使用夹具。

125 项相关单元/接口测试和 15 项浏览器场景通过；安装指引、恢复检测、缺失 CLI 时阻止扫码、页签错误入口均有浏览器回归。本机只读探测确认已有 CLI 1.0.98 可运行，没有安装/升级真实 CLI，也没有改变飞书账号授权或发送真实消息。真实账号的文档及消息操作需安装插件后验收。
