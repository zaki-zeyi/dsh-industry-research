# 架构

插件由 Cordis 服务插件、DSH 客户端桥接、React 界面、Express API 和 SQLite 元信息存储构成。既有宿主/飞书接入来自本机 `调研工作台` 项目，本实现使用独立插件 ID、服务路由、消息协议与数据目录。

- `plugin/index.mjs` 注册 `/industry-research/status` 与 `/industry-research/session`，启动本机服务；`plugin/client.js` 映射宿主原生聊天组件。
- `src/IndustryApp.jsx` 提供全量信息库、友商分析、历史任务和调研配置。`src/main.jsx` 复用飞书扫码与根目录弹窗。
- `server/industry.mjs` 提供默认配置、输入校验、资料库索引合并和已知索引读取。公司索引按飞书应用 profile/App ID 和根目录隔离。
- `server/industry-prompt.mjs` 将公司、信源、维度、已有公司文档及索引链接传入宿主 Agent。要求每家公司独立文档、读取后增量更新、逐条来源及日期、冲突标识与图片原始链接。
- `server/analysis.mjs` 校验友商分析选择，确认参与公司均已有全量信息库文档，合并报告回执并维护按飞书应用与根目录隔离的报告索引。`server/analysis-defaults.mjs` 保存 PRD 原文默认 Prompt，`server/analysis-prompt.mjs` 将库内来源、历史索引和交付约束传给宿主 Agent。
- `server/native-sessions.mjs` 在插件统一 workspace 创建标准模式原生会话，任务级控制文件单独存储。用户继续对话和失败重试复用原会话。
- `server/service.mjs` 串行编排，保留任务记录、幂等键和执行轮次，接收逐家公司交付的回执。任务全部公司有交付链接才算完成；失败保留已完成公司，后续任务使用最新本地索引。
- 飞书根目录 token 与「全量信息库」「友商分析」子目录 token 分开保存。已完成公司链接和友商报告链接不可变，不同公司或不同分析任务不得共用文档。回执校验仍以 Agent 的结构化结果为依据，不等价于独立远端内容审计。
- Agent 维护飞书「公司索引」JSON 文档，工作台通过已知文档 URL 用 Lark CLI `docs +fetch` 刷新，无需目录枚举。没有索引链接时使用已持久化的交付索引。首次换机器需要已知索引元信息，当前不支持扫描任意旧文件夹自动发现未收录资料。
- Agent 在「友商分析」子目录维护「分析报告索引」JSON 文档。报告卡片只引用该索引与本地交付元信息，正文不落本地；索引刷新失败时保留已有卡片并显示可操作错误。
- 自定义信源与维度保存在 SQLite settings。报告正文保存在飞书；本机保存任务提示、链接、维度和统计，不包含报告正文副本。

真实资料检索、写入、文档内容去重及冲突样式由宿主 Agent 执行；付费/内部信源不可访问时不得编造。模型、工具和扫码授权必须在实际 DSH 环境配置。

## v0.2.0 / PRD449 友商分析

新增独立「友商分析」页签。可选公司限制为全量信息库中已有飞书文档链接的条目，至少两家；对比维度复用全量信息库配置，支持临时编辑默认 Prompt。任务只允许在 DSH 原生会话运行，并复用插件级工作区与原会话继续对话。

交付回执必须覆盖本次选择的全部公司和维度，并携带友商分析子目录 token、索引链接和报告元信息。报告链接、公司集合、维度集合、资料不足公司以及历史索引均做严格校验；重试沿用原报告与原会话，不重复创建文档。资料不足不阻断报告，但必须回传并在卡片标注。

## v0.1.1 / PRD169 修复

公司回执与远程索引均支持 UTC 和带时区偏移的 ISO8601 更新时间。索引读取沿用飞书绑定实际使用的 CLI 路径，错误区分索引格式、授权、文档权限、CLI 不可用与请求超时，不向前端暴露原始命令输出。手动刷新不受后台缓存轮询覆盖，错误持续显示到重试成功或主动关闭。

单轮调研上限调整为 30 分钟；上限内未结束的会话继续等待。发送新一轮指令清除上一轮结束标记。旧版 10 分钟误判的任务，仅在同一 requestId 的完整合法交付、正常轮次结束时间未超过 30 分钟时恢复完成状态；用户中断和真正超时不会自动恢复。
