# 保存锁异常回收

Agent 负责读取最新原文、合并增量和写入飞书。平台只在提交阶段授予保存权限，并在每条 CLI 写命令启动前检查执行绑定、宿主 turn 和本次保存许可。

- 任务失败、取消、宿主 turn 报错（包括额度耗尽）时，撤销该轮许可。宿主残留的 `working` 不再阻塞支持新协议的轮次。
- 没有在途写命令或目录准备时，自动释放锁并交接排队任务。
- 空闲许可默认五分钟过期，运行时每秒检查；准备目录和在途命令仍须等实际结束。每条写命令结束后重新计算空闲时间。
- 工作台重试获得新的执行绑定；原生 Retry 的新 turn 也必须重新申请许可。旧许可不能启动后续写命令，旧 `finish` 不能释放新轮次的锁。
- CLI 子进程退出后，包装器写入只含操作 ID、绑定和请求 ID 的本地结束记录，再发送 HTTP `finish`。结束回报丢失时，平台可用该记录补偿；服务重启后申请锁时也会检查。记录不保存报告正文或凭据。
- 在途记录按原资料库和原执行绑定保留，即使重试切换了应用或根目录，也不能提前交出旧资料库的锁。

安全边界：没有结束证明的在途写命令不会仅因超时、任务失败或服务重启而被清除。包装器被强杀且未写入结束记录时，仍须确认旧写入已经结束后处理，避免两轮同时写。旧版本缺少许可校验的会话维持保守阻断，须确认旧会话结束后从工作台重试以创建新协议的绑定。

该机制约束插件提供的 CLI 包装器；Agent 绕过包装器直接调用飞书的写入不在此互斥保证内。

验证：`tests/cloud-write-admission.test.mjs` 覆盖额度耗尽/失败后宿主事件丢失、空闲过期、在途命令延期交接、原生 Retry、旧许可拒写、目录准备、跨库重试及真实 CLI 子进程结束回报丢失。宿主交互与完整插件安装仍需单独验收。
