# 0.6.5 飞书保存与通知重试

- 真实 CLI 对照：auth status --json 未传 --verify 时 bot 不返回 verified 字段；原通知代码却要求该字段为 true，导致在发送前错误失败。日报、周报和内部资料通知现均传 --verify。
- 权限修复优先复用当前可验证的同应用 profile；历史通知可使用同应用当前 profile，但发送前严格核对原收件人和应用，禁止向切换后的其他账号发送。消息幂等键仍是任务ID。
- 本机保存失败自动最多尝试3次，耗尽后提供重试保存按钮，不重新登记应用或要求扫码。凭据仅在内存中保留10分钟，取消、关闭、成功或过期后清理；失败保留原绑定。
- CLI保存返回错误时先核验本次profile是否已真实写入，避免超时后重复创建；对外仅保留错误码、是否被终止和核验结果，不保留原始密钥输出。
- 两个卡片动作合并为重试通知：先发送，缺机器人权限时打开官方应用权限更新二维码；官方流程确认后自动重试一次并刷新卡片，不无限循环申请权限。
- 177 项服务测试、19 项浏览器测试通过。浏览器覆盖免扫码保存重试、授权后自动补发与卡片更新。保存错误此前的底层日志已丢失；本轮使用临时诊断profile验证，本机CLI当前能正常保存，不能证明历史保存失败的具体系统原因。
- 包含0.6.4的共享调度归属与旧包卸载修复；不要再安装0.6.3。
