# DSH 行研工作台 0.8.3

发布日期：2026-11-05

## 飞书扫码登录修复

- 修复应用登记扫码二维码把绝对路径传给本机 Lark CLI 的问题。CLI 现在固定收到 `./qrcode.png`，文件通过本次流程专用的临时工作目录落盘。
- 修复个人授权扫码二维码的同类问题：`feishu-binding.mjs` 与 `feishu-registration.mjs` 共用同一套二维码参数、路径和 PNG 校验逻辑，避免后续再次分叉。
- CLI 返回成功但二维码文件缺失、超过 1 MB 或不是 PNG 时，立即按二维码生成失败处理，不再让页面停留在“二维码生成中”。
- 二维码生成失败现在显示明确的 `LARK_QRCODE_GENERATION_FAILED` 提示；原绑定保留，可重新获取二维码。不会再使用“飞书网页可能已完成配置”这种无法验证的兜底描述。
- 应用登记等待期间会立即校验二维码文件；扫码、应用登记、个人授权和换取凭据的既有流程保持不变。

## 回归覆盖

- 新增注册二维码相对路径断言：传入 CLI 的输出必须是 `./qrcode.png`，实际文件必须位于该流程的临时目录。
- 新增个人授权二维码相对路径与绝对落盘位置一致性断言。
- 新增无效 PNG、二维码生成失败和错误提示分类测试。
- 全部飞书业务、API 与授权恢复测试 62/62 通过。
